# Spring MVC 인증 1~3단계

## 요구사항

- POST "/login" 요청 시 이메일과 비밀번호로 로그인한다.
- 로그인에 성공하면 JWT를 생성하여 `token` 쿠키로 응답한다.
- GET "/login/check" 요청 시 쿠키의 토큰으로 로그인 회원 정보를 조회한다.
- 쿠키의 인증 정보를 이용해 로그인 회원을 컨트롤러 메서드에 주입한다.
- 예약 요청에 이름이 없으면 로그인 회원의 이름으로 예약한다.
- 예약 요청에 이름이 있으면 해당 이름으로 회원을 조회하여 예약한다.
- 관리자 권한을 가진 회원만 `/admin`과 하위 관리자 페이지에 접근할 수 있다.
- 관리자 권한이 없는 회원의 관리자 페이지 요청에는 401을 응답한다.

## 적용 사항

- JWT 생성과 해석을 담당하는 `JwtTokenProvider`를 추가했다.
- JWT의 subject에는 회원 id만 저장하고, 인증 시점의 최신 회원 정보를 DB에서 조회한다.
- 생성된 JWT를 `HttpOnly`가 적용된 `token` 쿠키로 응답했다.
- 로그인 확인 응답에는 로그인한 회원의 이름을 반환한다.
- 로그인 회원 정보를 표현하는 `LoginMember`를 추가했다.
- `LoginMemberArgumentResolver`에서 쿠키의 JWT로 로그인 회원을 조회하도록 인증 로직을 분리했다.
- Argument Resolver를 `WebMvcConfigurer`에 등록했다.
- 예약 요청의 이름 유무에 따라 예약자를 결정하도록 예약 생성 로직을 변경했다.
- `AdminInterceptor`에서 컨트롤러 호출 전에 로그인 회원의 권한을 확인한다.
- `WebMvcConfigurer`에 인터셉터를 등록하여 `/admin/**` 요청에 관리자 권한을 검사한다.
- 관리자 권한이 없으면 요청 처리를 중단하고 401을 응답한다.
- 잘못되거나 만료된 토큰, 토큰에 해당하는 회원이 없는 경우 401을 응답하도록 처리했다.
- 회원, 예약, 시간, 테마의 필수 입력값이 올바르지 않으면 400을 응답하도록 처리했다.
- 요청한 회원, 예약, 시간, 테마가 존재하지 않으면 404를 응답하도록 처리했다.
- 중복된 이메일, 예약, 시간이 등록되면 409를 응답하도록 처리했다.
- 예약 생성 시 날짜와 시간을 검증하여 과거 예약을 방지했다.
- 시간과 예약의 중복을 방지하기 위해 DB에 유니크 제약조건을 추가했다.
- 삭제된 시간을 다시 등록하면 새로운 데이터를 생성하지 않고 기존 시간을 복구하도록 처리했다.
- JWT에 발급 시각과 1시간의 만료 시간을 설정했다.

# Spring Data JPA 4~6단계

## 요구 사항
- JDBC 기반 데이터 접근 방식을 Spring Data JPA 기반으로 전환한다.
- 회원, 테마, 시간, 예약 데이터를 엔티티로 관리한다.
- 예약은 시간, 테마, 회원과의 관계를 통해 관리한다.
- 로그인한 회원은 자신의 예약 목록만 조회할 수 있다.
- `GET /reservations-mine` 요청 시 예약 번호, 테마, 날짜, 시간, 예약 상태를 반환한다.
- 로그인한 회원은 예약 대기를 신청할 수 있고, 신청한 예약 대기를 취소할 수 있다.
- 내 예약 목록 조회 시 일반 예약과 예약 대기를 함께 반환한다.
- 예약 대기 상태에 현재 대기 순번을 표시한다.

## 적용 사항
- `Time`, `Theme`, `Member`, `Reservation`을 JPA 엔티티로 매핑했다.
- JDBC DAO를 `JpaRepository` 기반 Repository로 전환했다.
- `Reservation`에서 `Time`, `Theme`, `Member`를 다대일 연관관계로 매핑했다.
- 삭제되지 않은 시간과 테마만 조회하도록 JPA 쿼리 메서드를 정의했다.
- 시간, 회원 이메일, 예약의 중복 방지를 위한 유니크 제약 조건을 엔티티 매핑에 반영했다.
- `LoginMember`에 회원 id를 추가해 로그인 회원을 식별하도록 했다.
- 로그인한 회원의 id를 기준으로 예약을 조회하는 메서드와 `MyReservationResponse` DTO를 추가했다.
- `Waiting` 엔티티를 추가하고 회원, 테마, 시간과 다대일 연관관계로 매핑했다.
- `POST /waitings`로 예약 대기를 생성하고 `DELETE /waitings/{id}`로 예약 대기를 취소하도록 구현했다.
- JPQL과 `WaitingWithRank` 객체를 사용해 같은 날짜, 테마, 시간 기준의 대기 순번을 조회했다.
- 내 예약 목록에서 일반 예약과 예약 대기를 하나의 응답 목록으로 합쳐 반환하도록 수정했다.
- 동일한 회원의 같은 날짜, 테마, 시간 대기를 DB 유니크 제약으로 방지하고, 중복 요청에 409를 응답하도록 처리했다.
- 예약 대기 취소 시 로그인한 회원과 대기 신청 회원이 다르면 403을 응답하도록 처리했다.

# Spring Core(배포) 7~9 단계

## 요구사항
- JWT 생성과 정보 추출 로직을 `roomescape` 외부의 `auth` 패키지로 분리한다.
- 외부 JWT 클래스를 `@Bean`에 등록한다.
- 관리자 페이지 접근 시 JWT에 담긴 권한을 사용해 불필요한 DB 조회를 줄인다.
- 실행 환경에 따라 초기 데이터를 구분하여 저장한다.
- 일반 실행에서는 회원만, 테스트에서는 회원/테마/시간/예약 데이터를 초기화한다.
- 저장소가 없으면 지정한 브랜치를 클론하여 배포를 준비한다.
- 최신 코드를 받아 빌드하고, 기존 애플리케이션을 종료한 뒤 새 애플리케이션을 실행한다.

## 적용사항
- `AuthConfiguration`의 `@Bean`으로 JWT 객체를 생성하고 등록했다.
- 설정 클래스에서 `@Value`로 비밀 키와 만료 시간을 읽어 JWT 객체의 생성자에 전달했다.
- JWT 생성 시 `Member` 객체 대신 회원 ID와 권한을 전달하도록 변경했다.
- 관리자 페이지의 권한 검사에 JWT 정보를 사용하도록 변경해 인증용 회원 조회를 제거했다.
- `CommandLineRunner`를 구현하여 애플리케이션 시작 시 초기 데이터를 저장하도록 했다.
- `@Profile`로 `DataLoader`와 `TestDataLoader`를 실행 환경별로 분리했다.
- `deploy.sh`에 저장소 클론, 최신 코드 반영, 빌드, 기존 애플리케이션 종료와 새 실행 과정을 작성했다.
- PID와 실행 명령을 확인하여 종료 대상을 구분하고, `prod` 프로필로 백그라운드 실행하도록 했다.
- 실행 PID와 로그를 `run` 폴더에 기록하고, HTTP 응답으로 서버 기동을 확인했다.
